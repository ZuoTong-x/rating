# 平台分阶段优化计划

目标是在保持业务行为和 API 响应兼容的前提下，优化后端结构、缩略图数据路径、表设计和前端维护性，并逐步转换后端 TypeScript。每一项修改完成后运行相关测试及全量测试；未通过就先修复，不继续推进。当前只修改本地代码并在本地数据库验证，不执行容器构建、线上迁移或发布。

| 步骤 | 工作 | 进入下一步的门槛 |
| --- | --- | --- |
| 1. 建立基线 | 记录代码、工作区、启动方式、关键接口耗时和查询计划，准备独立本地 PostgreSQL。 | 现有服务端测试、前端类型检查通过；本地 API、迁移服务和两个 Worker 可启动；结果留档。 |
| 2. 补关键流程测试 | 覆盖登录、ZIP 导入、默认任务锁、任务生成与解锁、打分提交、参考图、缩略图暂停恢复、导出和失败回滚。 | 新旧测试通过；人工走通“导入→发任务→打分→导出”。 |
| 3. 整理后端结构 | 按 `routes/`、`services/`、`repositories/` 迁出 `app.js` 的业务逻辑和 SQL，每次迁一个业务域。 | 每个域迁出后运行相关测试和全量服务端测试，核对路由、权限、响应和数据库写入。 |
| 4. 优化缩略图数据路径 | 用汇总表和状态定位列表与队列；核对回填、失败恢复、暂停、多图包与重复导入。只有实测需要才增加任务表图包字段。 | 明细与汇总一致；两个 Worker 不重复领取、不漏领或处理停用图包；查询计划与耗时优于基线。 |
| 5. 优化表结构与迁移 | 使用版本化增量迁移；逐一审查重复索引、`rating_tasks` 索引、项目图包双重关联及命名不符的外键。 | 旧结构到新版与重复迁移通过；核对行数、关联、统计和查询计划；每项结构调整有回退步骤。 |
| 6. 转换后端 TypeScript | JS/TS 共存，按数据库边界、服务、路由、Worker 和入口逐组转换。 | 每组类型检查、全量测试和本地启动通过；源码与本地编译产物均完成关键流程。 |
| 7. 整理前端 | 按上传、导出、任务等职责拆分请求服务和页面逻辑，按需加载大依赖和 UI 组件。 | `vue-tsc` 通过；人工核对管理端和打分页关键操作。 |
| **8. 清理旧代码与迭代残留** | 盘点不再引用的旧入口、重复实现、临时兼容分支、废弃脚本与依赖。先用代码搜索和运行路径确认无调用，区分仍有审计价值的历史修复记录；只删除已证明无用的代码，更新文档和脚本清单。 | 每批清理前后记录文件与引用；服务端全量测试、前端类型检查、本地完整流程均通过；迁移历史和线上修复审计记录保留。 |
| 9. 本地终验 | 在独立本地库重复执行迁移、API 与 Worker 启动、导入→发任务→打分→导出、缩略图暂停恢复、重复图包与批量下发；复查源码、锁文件和文档。 | 全部本地测试与人工关键操作通过，基线和剩余限制记录清楚。容器构建与线上发布不属于当前范围。 |

首轮结构整理和 TS 转换不改变公开 API 的路径、参数、响应字段和任务状态含义。`rating_tasks` 保持任务事实来源；项目、打分人和缩略图汇总数据可核对、可重算。物理索引损坏单独排查，不用表结构优化替代修复。

实施进度和本地测量见 [优化实施基线](OPTIMIZATION_BASELINE_20261118.md)，索引审查见 [表结构与索引审查](SCHEMA_INDEX_AUDIT_20261118.md)。
